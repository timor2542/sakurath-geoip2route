# คู่มือการใช้งาน SakuraTH GeoIP2Route

คู่มือนี้เป็นต้นฉบับข้อความสำหรับอธิบายการใช้งานจริงและนำไปจัดหน้าเป็นภาพใน Photoshop ได้ ภาพหน้าจอควรถ่ายจากแอปรุ่นเดียวกับเอกสาร เพื่อให้ชื่อปุ่ม ตัวเลข และลำดับหน้าจอตรงกัน

- แอปออนไลน์: <https://sakurath-geoip2route.netlify.app/>
- ซอร์สโค้ด: <https://github.com/timor2542/sakurath-geoip2route>
- เวอร์ชันเอกสาร: `v1.8.0`

## 1. แอปนี้ใช้ทำอะไร

SakuraTH GeoIP2Route ใช้ข้อมูลตำแหน่ง IP จาก IP2Location เพื่อทำงานหลักสองแบบ:

1. **IP Compare** — เลือก IP สองจุดเป็น A และ B แล้วเปรียบเทียบระยะทาง ประเทศ เมือง ISP, ASN, ประเภทเครือข่าย และเขตเวลา
2. **Server Ranking** — เลือก IP หนึ่งจุดเป็นตำแหน่งอ้างอิง แล้วจัดอันดับจุดอื่นในรายการเป็นตัวเลือกเซิร์ฟเวอร์ด้วยหลักฐานที่แสดงให้ตรวจสอบได้

แอปไม่ใช่เครื่องมือ Traceroute, ICMP Ping, Load Balancer หรือระบบตัดสินใจย้าย Traffic อัตโนมัติ เส้นบนแผนที่แสดงความสัมพันธ์ทางภูมิศาสตร์ ไม่ใช่เส้นทางจริงของ Packet

> **ข้อความสั้นสำหรับภาพเปิด:** เปรียบเทียบตำแหน่ง IP และจัดอันดับเซิร์ฟเวอร์ พร้อมแสดงที่มาของคะแนนอย่างโปร่งใส

## 2. ทำความรู้จักหน้าจอ

หน้าจอ Desktop แบ่งเป็นสี่ส่วนหลัก:

1. **แถบด้านบน** — โลโก้ วันและเวลาของประเทศอ้างอิง ปุ่ม Refresh, Help, ภาษา และธีม
2. **แถบด้านซ้าย** — เลือกโหมด เพิ่ม IP นำเข้า CSV เลือก A/B หรือเลือก IP อ้างอิง
3. **แผนที่ตรงกลาง** — แสดงหมุด เส้น Grid มาตราส่วน และปุ่มซูม
4. **แถบด้านขวา** — แสดงผลเปรียบเทียบหรือผลจัดอันดับโดยละเอียด

ด้านล่างของแผนที่คือ **Activity Console** สำหรับดูเหตุการณ์ที่เกิดขึ้นในเบราว์เซอร์รอบปัจจุบัน

### ความหมายของสัญลักษณ์บนแผนที่

- `A` สีชมพู: จุดแรกในการเปรียบเทียบ
- `B` สีเหลือง: จุดที่สองในการเปรียบเทียบ
- `SRC` สีเขียว: IP อ้างอิงในโหมดจัดอันดับ
- `1`, `2`, `3`, ...: อันดับของเซิร์ฟเวอร์
- หมุดสีเทา: จุดอื่นที่ยังไม่ได้เลือก
- `LIVE`: ข้อมูลที่ Lookup จาก IP2Location
- `SAMPLE`: ข้อมูลตัวอย่างที่มากับโปรเจกต์
- `SIMULATED`: ข้อมูลจำลองสำหรับสาธิตความแตกต่างของหลักฐาน

> **ภาพที่ควรถ่าย 1 — ภาพรวมแอป:** ใช้หน้าจอ Desktop แนวนอน ให้เห็นแถบซ้าย แผนที่ แถบขวา และ Activity Console ในภาพเดียว ใส่หมายเลขกำกับ 1–4 ตามส่วนประกอบด้านบน

## 3. วัน เวลา ภาษา และธีม

เวลาบนหัวแอปอ้างอิงเขตเวลาของจุดที่กำลังใช้งาน:

- โหมด **IP Compare** ใช้เขตเวลาของจุด A
- โหมด **Server Ranking** ใช้เขตเวลาของ `SRC`
- หากยังไม่ได้เลือก ระบบใช้จุดแรกในรายการ และใช้เวลาของอุปกรณ์เมื่อไม่มีข้อมูลจุด

ภาษาไทยแสดงเวลาแบบ 24 ชั่วโมงและใช้ พ.ศ. โดยวาง `พ.ศ.` ไว้หน้าปี ส่วนภาษาอังกฤษแสดงเวลาแบบ 12 ชั่วโมงพร้อม AM/PM และใช้ `AD`

ปุ่มธีมมีสามแบบ:

- รูปดวงอาทิตย์: Light theme
- รูปดวงจันทร์: Dark theme
- วงกลมครึ่งสี: Automatic theme ซึ่งเปลี่ยนตามเวลาของอุปกรณ์

การเลือกภาษา ธีม และสถานะเปิด/ปิด Activity Console จะถูกจำไว้ในเบราว์เซอร์

> **ภาพที่ควรถ่าย 2 — ส่วนหัว:** ครอปเฉพาะหัวแอป ให้เห็นวัน เวลา รหัสประเทศ เขตเวลา ปุ่ม EN/TH และปุ่มธีม ใส่ลูกศรอธิบายว่าเวลาอ้างอิงจาก A หรือ SRC

## 4. เริ่มทดลองอย่างรวดเร็ว

เมื่อเปิดแอปครั้งแรกจะมีตำแหน่งตัวอย่าง 8 จุด สามารถเลือกหมุดและเปลี่ยนโหมดได้ทันที

ปุ่ม **Try Demo — Simulated Data** เพิ่มชุดข้อมูลจำลองและเปิดโหมด Server Ranking เพื่อสาธิตว่า “เซิร์ฟเวอร์ที่อยู่ใกล้ที่สุด” อาจไม่ใช่ “เซิร์ฟเวอร์ที่ตอบสนองเร็วที่สุด” ข้อมูลจำลองจะแสดงป้ายกำกับชัดเจนและไม่ปะปนกับผลวัดจริง

ปุ่ม **Load Live Test Example** เตรียมตัวอย่าง `target` และ `probe_url` ในหน้าต่างนำเข้า ผู้ใช้ยังต้องเริ่ม Lookup และการวัด HTTP ด้วยตนเอง

> **ข้อความสั้นสำหรับภาพ:** ทดลอง UI ได้ทันทีด้วยข้อมูลตัวอย่าง และแยกข้อมูลจำลองออกจากผลวัดจริงอย่างชัดเจน

## 5. เพิ่ม IP หนึ่งรายการ

### 5.1 เพิ่ม Public IP หรือ Hostname

1. ไปที่หัวข้อ **ADD IPs TO THE LIST**
2. พิมพ์ Public IPv4, IPv6 หรือ Hostname เช่น `8.8.8.8`, `2606:4700:4700::1111` หรือ `example.com`
3. กดปุ่ม `+` หรือกด Enter
4. รอแถบสถานะ Lookup
5. เมื่อสำเร็จ หมุดใหม่จะปรากฏบนแผนที่และรายการด้านซ้าย

หาก Hostname ชี้ไปยัง IP ที่มีอยู่แล้ว ระบบจะอัปเดตข้อมูลจุดเดิมและไม่สร้างหมุดซ้ำ

ระบบไม่รับ Local/Private/Reserved IP, URL ที่มีชื่อผู้ใช้หรือรหัสผ่าน และค่าที่มี Port กำหนดเองในช่อง Target

### 5.2 เพิ่ม IP ปัจจุบัน

1. กด **Add current IP**
2. ระบบตรวจหา Public IP ของการเชื่อมต่อที่เปิดแอป
3. IP ที่พบจะถูกเพิ่มหรืออัปเดตในรายการ
4. จุดดังกล่าวจะเป็น A ในโหมดเปรียบเทียบ และเป็น `SRC` ในโหมดจัดอันดับ

หาก Live API ใช้งานไม่ได้ ระบบจะแสดงข้อผิดพลาดโดยไม่สร้างข้อมูลตำแหน่งปลอม

> **ภาพที่ควรถ่าย 3 — เพิ่ม IP:** ครอปแถบซ้ายตั้งแต่ปุ่ม Add current IP ถึงช่องเพิ่ม IP ใส่หมายเลขขั้นตอนที่ช่องกรอก ปุ่ม `+` และข้อความสถานะ

## 6. วางรายการหลาย IP

1. กด **Paste list**
2. ใส่หนึ่ง IP หรือ Hostname ต่อหนึ่งบรรทัด
3. ตรวจจำนวนรายการเดิมและรายการที่จะนำเข้า
4. เลือกวิธีรวมข้อมูล
5. กดปุ่มเริ่ม Lookup

รองรับบรรทัด Comment ที่ขึ้นต้นด้วย `#` และระบบจะตัดรายการ Target ที่ซ้ำกันก่อนเริ่ม Lookup สูงสุด 200 Target ต่อการนำเข้าหนึ่งครั้ง

ตัวอย่างรายการ:

```text
8.8.8.8
1.1.1.1
example.com
2606:4700:4700::1111
```

> **ภาพที่ควรถ่าย 4 — Paste list:** เปิดหน้าต่าง Paste list พร้อมข้อมูล 4 บรรทัด ให้เห็นจำนวน Current list, Incoming list และตัวเลือก Append/Replace

## 7. นำเข้า CSV

### 7.1 รูปแบบขั้นต่ำ

ไฟล์ต้องมีคอลัมน์ Target อย่างน้อยหนึ่งคอลัมน์ ลำดับคอลัมน์ไม่ตายตัว เพราะระบบตรวจจากชื่อ Header

```csv
ip
8.8.8.8
1.1.1.1
```

ชื่อ Header ที่ใช้เป็น Target ได้:

`target`, `ip`, `ip_address`, `address`, `hostname`, `host`

### 7.2 รูปแบบพร้อม Probe URL

```csv
target,probe_url
dns.google,https://dns.google/resolve?name=example.com&type=A
```

ชื่อ Header ของ Probe URL ที่รองรับ:

`probe_url`, `probe`, `health_url`

Probe URL เป็นข้อมูลไม่บังคับ แต่ต้องเป็น HTTPS และ Hostname ต้องตรงกับ Target ของแถวนั้น

### 7.3 คอลัมน์อ้างอิง

ระบบสามารถระบุบทบาทของคอลัมน์ต่อไปนี้เพื่อช่วยตรวจไฟล์:

- ประเทศ: `country_name`, `country`, `country_full_name`
- รหัสประเทศ: `country_code`, `country_short`, `country_iso`, `iso2`
- ภูมิภาค: `region_name`, `region`, `state`, `state_name`
- เมือง: `city_name`, `city`
- พิกัด: `latitude`/`lat` และ `longitude`/`lng`/`lon`
- เครือข่าย: `isp`, `isp_name`, `asn`, `as_number`, `usage_type`, `network_type`
- เขตเวลา: `timezone`, `time_zone`

คอลัมน์เหล่านี้เป็น **Reference only** ข้อมูลตำแหน่งจริงยังมาจากผล Lookup ของ Target ส่วนคอลัมน์ที่ระบบไม่รู้จักจะแสดงเป็น **Ignored**

### 7.4 ตรวจไฟล์ก่อนนำเข้า

1. กด **Import CSV** และเลือกไฟล์ `.csv` หรือ `.txt`
2. ระบบอ่านไฟล์ภายในเบราว์เซอร์ก่อน โดยยังไม่เริ่ม Lookup
3. ตรวจสถานะ **CSV structure detected**
4. ตรวจกล่อง **Column mapping** ว่าคอลัมน์ Target และ Probe ถูกต้อง
5. ตรวจตัวเลข Rows checked, Valid rows และ Invalid rows
6. ตรวจตัวอย่างสามแถวแรกในตาราง Preview
7. หากมีปัญหา ระบบระบุหมายเลขแถวและปิดปุ่มนำเข้าไว้จนกว่ารูปแบบจะถูกต้อง

ข้อผิดพลาดที่ตรวจได้ เช่น ไม่มี Target header, มี Target/Probe ซ้ำ, Target ไม่ถูกต้อง, Probe URL ไม่ถูกต้อง, Probe ไม่ตรงกับ Target, มีคอลัมน์เกินจาก Header หรือปิด Quote ไม่ครบ

ข้อจำกัดคือไฟล์ละไม่เกิน 1 MiB และไม่เกิน 200 Target ที่ไม่ซ้ำ

> **ภาพที่ควรถ่าย 5 — CSV ถูกต้อง:** ใช้ไฟล์ตัวอย่างที่มี `country_name,city_name,ip` ให้เห็น Column mapping, จำนวนแถว และ Preview สามแถวแรก
>
> **ภาพที่ควรถ่าย 6 — CSV ไม่ถูกต้อง:** ใช้ไฟล์ที่มี Target ผิดหนึ่งแถว ให้เห็น Invalid rows และหมายเลขแถวที่ต้องแก้ ใช้สีแดงเฉพาะจุดผิด

### 7.5 เลือกว่าจะเก็บรายการเดิมหรือไม่

ในหน้าต่างนำเข้ามีสองตัวเลือก:

- **Append to current list — Recommended:** เก็บรายการเดิมและเพิ่ม Target ใหม่ ระบบรวม IP ซ้ำให้อัตโนมัติ
- **Replace current list:** ใช้ผลนำเข้าชุดใหม่แทนรายการเดิมทั้งหมด

เมื่อเลือก Replace ระบบจะแสดงคำเตือน หาก Lookup ชุดใหม่ล้มเหลวทั้งหมด ระบบจะยกเลิกการแทนที่และเก็บรายการเดิมไว้ เพื่อป้องกันข้อมูลหายจากความผิดพลาดของ API หรือเครือข่าย

ระหว่าง Lookup จะแสดง Progress ทั้งจำนวนและแถบสถานะ โดยประมวลผลพร้อมกันสูงสุดสามรายการ

> **ภาพที่ควรถ่าย 7 — ตัวเลือกนำเข้า:** เน้นวงรอบ Append และ Replace พร้อมข้อความสั้น “เก็บรายการเดิม” และ “แทนที่รายการเดิม”

## 8. เปรียบเทียบ IP สองจุด

1. เลือกแท็บ **IP Compare**
2. เลือกหมุดบนแผนที่หรือแถวใน **MAP POINTS** หนึ่งรายการ จุดนั้นจะเป็น A
3. เลือกอีกรายการ จุดนั้นจะเป็น B
4. หากเลือกจุดที่สาม ระบบจะแทนที่ B โดยคง A ไว้
5. ดูเส้นเชื่อม A–B และผลเปรียบเทียบด้านขวา

ผลลัพธ์ประกอบด้วย:

- Great-circle distance หรือระยะทางสั้นที่สุดบนผิวโลก
- Country
- Region / city
- ISP
- ASN
- IP usage type
- Timezone
- สรุปว่า Country, ASN และ Network type เหมือนหรือต่างกัน

ตำแหน่งทั้งหมดเป็นค่าประมาณจาก IP geolocation โดย Anycast IP อาจแสดงตำแหน่งเครือข่ายต่างกันได้

> **ภาพที่ควรถ่าย 8 — ผลเปรียบเทียบ:** เลือก Bangkok เป็น A และ Singapore เป็น B ให้เห็นหมุด เส้นเชื่อม การ์ด A/B ตัวเลขระยะทาง และตารางเปรียบเทียบ
>
> **คำกำกับภาพ:** เลือกสองจุดเพื่อเปรียบเทียบตำแหน่งและข้อมูลเครือข่ายแบบเคียงข้างกัน

## 9. จัดอันดับเซิร์ฟเวอร์

### 9.1 เลือกตำแหน่งอ้างอิง

1. เลือกแท็บ **Server Ranking**
2. เลือก IP ที่ต้องการเป็น **Geographic reference IP**
3. จุดอ้างอิงจะแสดงเป็น `SRC` และไม่ถูกนำมาจัดอันดับเป็น Candidate
4. IP อื่นทั้งหมดในรายการจะกลายเป็นตัวเลือกเซิร์ฟเวอร์

การเปลี่ยน `SRC` มีผลต่อระยะทาง แต่ไม่เปลี่ยนต้นทางของ HTTP request เพราะ HTTP วัดจากเบราว์เซอร์ที่เปิดแอปเสมอ

### 9.2 Geographic fit

เลือก **Geographic fit** เมื่อต้องการจัดอันดับจากตำแหน่งและประเภทเครือข่าย:

```text
Distance score = clamp(100 - distance_km / 200.37, 0, 100)
Geographic fit = 80% Distance score + 20% Network preference
```

Network preference ที่ใช้ในแอป:

- DCH/CDN = 100
- ISP = 82
- MOB = 70
- อื่นหรือไม่ทราบ = 76

คะแนน 0–100 เป็นคะแนนเปรียบเทียบจากกติกาของผลิตภัณฑ์ ไม่ใช่เปอร์เซ็นต์ SLA และไม่รับประกันประสิทธิภาพเครือข่ายจริง

### 9.3 Browser HTTP

เลือก **Browser HTTP** เมื่อต้องการจัดอันดับจากเวลาตอบสนองที่วัดจริง:

```text
HTTP score = clamp(100 - median_http_ms / 4, 0, 100)
Browser HTTP fit = 80% HTTP score + 20% Network preference
```

การตั้ง Probe URL:

1. เลือก Candidate จากตารางด้านขวา
2. ใส่ URL ของ Health endpoint หรือไฟล์ขนาดเล็กในช่อง **Candidate HTTPS probe URL**
3. URL ต้องเป็น HTTPS, Hostname/IP ต้องตรงกับ Candidate, ไม่มี Custom port, Credentials หรือ Fragment และเซิร์ฟเวอร์ต้องอนุญาต CORS
4. กด **Save & measure** หรือ **Measure now**
5. ทำซ้ำกับ Candidate อื่น หรือใช้ **Measure configured URLs** เพื่อวัดทุก URL ที่พร้อม

แต่ละ Candidate ถูกเรียก GET ตามลำดับสามครั้ง ใช้ค่ามัธยฐานของครั้งที่สำเร็จ และมี Timeout 4.5 วินาทีต่อครั้ง แอปวัดถึง Response headers และยกเลิก Body เพราะไม่ได้ทดสอบ Throughput

หากวัดไม่สำเร็จ ระบบแสดงว่าไม่มีผลวัดและไม่สรุปว่าเซิร์ฟเวอร์ Offline เนื่องจาก CORS, TLS, Redirect หรือการเชื่อมต่อของเบราว์เซอร์อาจเป็นสาเหตุได้

### 9.4 อ่านผลจัดอันดับ

การ์ด **RECOMMENDED SERVER** แสดง:

- Candidate ที่ได้คะแนนสูงสุด
- คะแนนรวมและระดับ Excellent/Good/Fair/Poor
- HTTP timing หรือสถานะ Not tested
- ระยะทางจาก `SRC`
- ประเภทเครือข่าย
- ชนิดหลักฐาน Estimated, Measured หรือ Simulated
- Contribution ของแต่ละองค์ประกอบ
- เหตุผลที่ Candidate นี้เป็นอันดับหนึ่งและส่วนต่างจากอันดับสอง

ตาราง **SERVER RANKING** แสดงทุก Candidate ตามอันดับ เมื่อคลิกแต่ละแถวจะเห็น IP, ISP, ASN, Timing, Distance, Score และข้อมูล Probe โดยละเอียด

> **ภาพที่ควรถ่าย 9 — ตั้งค่า Ranking:** ให้เห็น `SRC`, ตัวเลือก Rank using และ Candidate ทั้งหมดบนแผนที่
>
> **ภาพที่ควรถ่าย 10 — Recommended Server:** ครอปแถบขวาให้เห็นคะแนนวงกลม Metric, Score contribution และ Why this candidate ranks first
>
> **ภาพที่ควรถ่าย 11 — HTTP Probe:** ใส่ Probe URL ที่ถูกต้องและแสดงผล `3/3` พร้อม Median timing ระบุใต้ภาพว่า “วัดจากเบราว์เซอร์ ไม่ใช่ Ping”

## 10. ส่งออกผลลัพธ์

ในโหมด Server Ranking สามารถกด:

- **Export JSON** สำหรับข้อมูลแบบมีโครงสร้างและรายละเอียด Formula/Components
- **Export CSV** สำหรับเปิดในโปรแกรม Spreadsheet

ไฟล์ส่งออกบันทึกอันดับ Target/IP ประเทศ Basis, Score, Reference IP, Distance, ชนิดและต้นทางการวัด, Median HTTP, จำนวนครั้งที่สำเร็จ, เวลา UTC, Probe URL และ Contribution ของคะแนน

ข้อมูล CSV ที่อาจถูกตีความเป็น Spreadsheet formula จะถูกป้องกันก่อนส่งออก

> **ภาพที่ควรถ่าย 12 — Export:** ครอปปุ่ม Export JSON/CSV และวางภาพตัวอย่างไฟล์ผลลัพธ์ข้างกัน

## 11. ใช้แผนที่

- `+` ซูมเข้า
- `−` ซูมออก
- ไอคอนมุมทั้งสี่ จัดให้ทุกจุดอยู่ในขอบเขตแผนที่
- เส้น Grid ช่วยอ่านสัดส่วนพื้นที่
- มาตรวัดมุมล่างขวาแสดงระยะทางโดยประมาณต่อหนึ่งช่อง Grid และเปลี่ยนตามระดับ Zoom
- คลิกหมุดเพื่อดูชื่อเมือง IP และข้อมูลเครือข่าย

เส้นเชื่อมในโหมด Compare และ Ranking เป็นเส้นภูมิศาสตร์เท่านั้น ไม่แสดงจำนวน Hop หรือเส้นทาง Packet จริง

## 12. ล้างและลบข้อมูล

คำสั่งแต่ละแบบทำงานต่างกัน:

- **Clear A/B selection:** ล้างเฉพาะสถานะ A และ B แต่เก็บรายการ IP และหมุดทั้งหมด
- **Clear ใน Activity Console:** ล้างเฉพาะข้อความกิจกรรม ไม่กระทบ IP หรือผลลัพธ์
- **ไอคอนถังขยะท้ายแถว:** เปิดหน้าต่างยืนยันเพื่อลบ IP รายการเดียว
- **Delete all:** เปิดหน้าต่างยืนยันเพื่อลบ IP และหมุดทุกจุด

หลังจากยืนยัน Delete all ระบบจะล้าง A/B, `SRC`, Candidate ที่เลือก และข้อมูล Probe ใน Workspace ปัจจุบันด้วย

> **ภาพที่ควรถ่าย 13 — ยืนยันการลบ:** ให้เห็นจำนวนจุดที่จะลบ ปุ่ม Cancel และปุ่มยืนยันสีเด่น หลีกเลี่ยงการแคปหลังลบจริงเพื่อเก็บข้อมูลตัวอย่างไว้

## 13. Activity Console

Activity Console แสดงเวลา ระดับเหตุการณ์ และข้อความ เช่น:

- `[INFO]` การเลือก การล้าง หรือการเริ่มทำงานทั่วไป
- `[WAIT]` กำลัง Lookup หรือตรวจวัด
- `[OK]` ทำงานสำเร็จ
- `[ERROR]` ทำงานไม่สำเร็จหรือสำเร็จเพียงบางส่วน
- `[DEMO]` โหลดข้อมูลจำลอง

Console เป็นข้อมูลของ Browser session ปัจจุบันและมีไว้ช่วยอธิบายขั้นตอน ไม่ใช่ Server log แบบถาวร สามารถยุบ ขยาย หรือล้างข้อความได้

> **ภาพที่ควรถ่าย 14 — Activity Console:** แสดงตัวอย่าง WAIT, OK และ ERROR โดยปิดบังข้อมูลที่ไม่ต้องการเผยแพร่

## 14. การใช้งานบนมือถือและการเข้าถึง

- บนหน้าจอแคบ แผนที่จะอยู่ด้านบนและ Panel จะเรียงลงมา
- ปุ่มหลักมีชื่อสำหรับ Screen reader และ Tooltip
- ใช้ Tab เพื่อเลื่อน Focus ระหว่าง Control
- กด Enter เพื่อส่งฟอร์มเพิ่ม IP
- กด Escape เพื่อปิด Dialog ที่ไม่ได้กำลังประมวลผล
- Dialog จำกัด Focus ให้อยู่ภายในหน้าต่างจนกว่าจะปิด
- แอปรองรับ Reduced motion จากการตั้งค่าระบบ

ควรทดลองอย่างน้อยหนึ่งภาพใน Mobile viewport และตรวจทั้งภาษาอังกฤษ/ไทย รวมถึง Light/Dark theme ก่อนทำคู่มือฉบับสุดท้าย

## 15. Checklist สำหรับการทำภาพใน Photoshop

1. ใช้ความละเอียดเดียวกันทุกภาพ เช่น `1920×1080`
2. ใช้ Browser zoom 100% และกดปุ่ม Fit all points ก่อนถ่ายภาพแผนที่
3. ใช้ข้อมูลตัวอย่างชุดเดียวกันทุกภาพ เพื่อให้ A/B, `SRC`, อันดับ และระยะทางต่อเนื่องกัน
4. เลือกภาษาให้ตรงกับคู่มือ ไม่ผสม EN/TH ในภาพเดียวโดยไม่จำเป็น
5. ครอปให้เห็นชื่อ Section ก่อนใส่ลูกศรหรือหมายเลขกำกับ
6. ใช้สีคำกำกับให้ตรงกับ UI: ชมพูสำหรับ A/อันดับหนึ่ง เหลืองสำหรับ B และเขียวสำหรับ `SRC`
7. อย่าบัง Attribution ของ Leaflet/OpenStreetMap
8. ปิดบัง API key, Token, URL ภายใน และข้อมูลส่วนบุคคลก่อนเผยแพร่
9. หลีกเลี่ยงการแต่งตัวเลขผลลัพธ์จนต่างจากค่าที่แอปแสดงจริง
10. ตรวจคำสะกด วันที่ เวอร์ชัน และลิงก์ก่อน Export ภาพ

## 16. ชุดข้อความสั้นสำหรับวางบนภาพ

- **ภาพรวม:** Compare IP locations and rank server candidates in one workspace.
- **เพิ่ม IP:** เพิ่ม Public IP, IPv6 หรือ Hostname แล้วให้ IP2Location เติมข้อมูลตำแหน่ง
- **CSV:** ตรวจ Header, Column mapping และแถวผิดก่อนเริ่ม Lookup
- **Import mode:** เลือกเพิ่มต่อจากรายการเดิม หรือแทนที่ทั้งรายการอย่างปลอดภัย
- **Compare:** เลือก A และ B เพื่อเปรียบเทียบตำแหน่งและข้อมูลเครือข่าย
- **Ranking:** เลือก `SRC` แล้วตรวจคะแนนและหลักฐานของ Candidate ทุกตัว
- **HTTP:** วัด HTTPS response จากเบราว์เซอร์ 3 ครั้งและใช้ค่ามัธยฐาน
- **Map:** Grid และมาตรวัดเปลี่ยนตาม Zoom เพื่อช่วยอ่านระยะทาง
- **Delete:** การล้าง Selection ต่างจากการลบ IP และทุกการลบมีหน้าต่างยืนยัน
- **Accuracy:** IP geolocation เป็นค่าประมาณ และเส้นบนแผนที่ไม่ใช่ Traceroute

## 17. ข้อจำกัดที่ควรระบุในคู่มือ

- ตำแหน่ง IP เป็นค่าประมาณ ไม่ใช่ GPS
- Anycast/CDN อาจ Resolve ไปยังตำแหน่งต่างกัน
- Great-circle distance ไม่ใช่ระยะทางเครือข่าย
- HTTP timing รวม DNS, Connection, TLS, Server processing และ Browser scheduling บางส่วน
- คะแนนเป็น Heuristic สำหรับช่วยเปรียบเทียบ ไม่ใช่ SLA หรือคำสั่ง Routing อัตโนมัติ
- รายการและผลวัดอยู่ใน Browser session และจะรีเซ็ตเมื่อ Reload
